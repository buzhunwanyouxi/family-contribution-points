# 家庭贡献评分奖励系统

> 把家务从"父母的唠叨"变成"家庭内部的公平游戏":**谁做了、做得多好、值多少分、能换什么,全家都看得见。**

一个面向家庭的开源 PWA(网页应用,可添加到手机主屏幕):父母可以给子女派活,子女也能给家人发委托;任务完成后上传照片或视频,由家人按**完成度百分比**打分,积分进入家庭内部的"劳动货币",最终兑换全家人自己商量的愿望。

---

## 这个项目最值钱的四个差异点

1. **双向任务市场** —— 不是"家长管孩子":母亲派哥哥去接弟弟放学,弟弟发题求辅导,姐姐攒分换 iPad。
2. **固定任务 + 临时任务双轨** —— 固定任务是家庭的日常基线(每天 14:00 洗碗),临时任务是今天的意外。
3. **家庭内部经济** —— 积分有产出(做任务)也有消费(兑愿望),由家庭自己定价。
4. **成员自定义愿望** —— 兑换目标不是平台预设的,弟弟的 iPad = 父亲定的 1000 分,还能多人一起攒。

## 核心规则(一句话版)

```
实得积分 = 完成度百分比(评分人平均值) × 该任务最高分
      洗碗最高 3 分 → 家人一致给 100% → 得 3 分
                    家人平均给 40%  → 得 1.2 分
```

- **创始人(家长)必须评分**,其他家庭成员可以选择评分;创始人一票定音,但他 24 小时没打分就先用其他人的平均分兜底,补分后覆盖重算。
- **日常固定任务只能由创始人创建**;临时任务任何人都能发。
- **积分兑换物品完全由家庭成员自定义**;愿望所需积分由创始人填写。
- **任务证据(照片/视频)只保留 72 小时**,到期自动删除(家人隐私优先,也省存储)。
- **积分永远同时显示三个数字**:累计获得 / 当前可用 / 已消费。

完整规则见 [`docs/PROJECT_GUIDE.md`](docs/PROJECT_GUIDE.md) —— 那是本项目的唯一权威依据。

## 技术形态:为什么是 PWA 而不是 App

| 需求 | 是否需要原生 App |
|---|---|
| 拍照/录像上传、看照片打分 | ❌ 浏览器完全能做 |
| 定时提醒 | ⚠️ 靠微信模板消息 + 短信,不是靠 App |
| 多人协作、权限、积分流水 | ❌ 纯服务端逻辑 |
| 全家各种安卓机(华为/小米/OPPO/vivo) | ❌ 越原生越麻烦 |

**用户使用链路**:家人收到链接 → 手机号登录 → 浏览器"添加到主屏幕" → 桌面出现图标、全屏运行、自动更新,永远不用重装。

技术栈:`React + Vite`(PWA 前端) + `Fastify`(后端) + `Prisma`(开发用 SQLite,生产用 PostgreSQL) + 对象存储(证据文件)。

## 快速开始

```bash
pnpm install
cp .env.example .env      # Windows: copy .env.example .env
pnpm db:migrate           # 建本地 sqlite 库
pnpm dev                  # api :3000 / web :5173
pnpm test
```

需要 Node.js ≥ 20 与 pnpm。

## 开发路线(4 周,每周都有能用的东西)

| 周 | 目标 | 家人能干什么 |
|---|---|---|
| W1 | 账号体系、创建/加入家庭、成员角色 | 全家账号建起来 |
| W2 | 固定任务管理、抢单、到期兜底指派、临时任务 | 每天 14:00 洗碗有人接 |
| **W3** | **证据上传、评分结算、积分三数、证据 72h 过期** | **产品可以真正用了(MVP)** |
| W4 | 愿望众筹、定价、月度报告、微信提醒 | 弟弟开始盯自己的 1000 分 |

详见 [`docs/ROADMAP.md`](docs/ROADMAP.md)。
**准备开工?先读 [`docs/DAY1-PLAN.md`](docs/DAY1-PLAN.md)** —— 三个人的分工、文件归属表、接口冻结清单、当天完成标准都在里面。

## 隐私与安全

- 家庭数据不对外分享、不做广告、不卖数据。
- 任务证据(可能包含未成年人影像)**72 小时后自动删除**,仅家庭成员可见,通过签名 URL 访问。
- 积分不涉及真实货币、不可交易、不可提现。

安全问题请按 [`SECURITY.md`](SECURITY.md) 私下报告,不要开公开 Issue。
