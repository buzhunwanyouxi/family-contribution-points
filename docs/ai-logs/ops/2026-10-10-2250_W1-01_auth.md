**建议先读**(这四处定死了边界,读完再进实现细节不会迷路):

4. `apps/api/src/routes/auth.ts` —— HTTP 层怎么装到**根实例**上,以及为什么不能用 `{ prefix }`。

**接着做最省事的顺序**(以 `W1-01` 剩余部分"找回密码"为例):

1. **先定端口,不选通道**:`notify` 模块目前是空的,不要顺手把短信/邮件一起做进来。
   在 `AuthRepository` 上加两个方法(写重置令牌、消费令牌),把"怎么发出去"留成一个注入端口;
2. **复用既有件**:哈希只走 `password.ts` 的 `hashPassword`;一次性令牌直接用 `TokenCodec`
   (`issue` 一个短 TTL 的 subject,别自己写签名);
3. **同步 Prisma 适配器**:`repository.prisma.ts` 是结构化类型,加方法时它不会自动报错,要手动补;
4. **测试照 `http.test.ts` 的 `inject` 风格**:端到端 + 契约一致性两层,不要只测纯函数。

**别踩的坑**(都是我踩过或见别人踩过的):

1. **不要另写认证中间件**:`app.requireAuth` / `currentUserId` 已装在**根实例**上,直接用;
2. **`declare module 'fastify'` 全项目只允许出现在 `apps/api/src/auth/types.ts`**(文件头与
   `declare module` 处各有一段醒目注释)—— 重复声明会编译冲突或**静默合并成怪类型**;
3. **错误响应只走一处**:`AuthError` + `toErrorBody`。我这次就因为 `requireAuth` 里**手写**了一个 401
   响应体,导致同一个 401 出现两种形状(见附录 A 问题 2);
4. **`server.ts` 里没有 Prisma 接线** → 默认是**内存仓储**,`pnpm dev` 重启即丢数据,
   接真库见 `CONTRACTS.md`「auth 模块交付说明」的 3 行接线;
5. **改 `CONTRACTS.md` 前先 `git fetch`**:本项目 `main` 推进很快,我已因它 rebase 两次。

**"看起来可以抄、但其实是权衡"的地方**(别当成标准照抄):

| 我的做法 | 真实性质 |
|---|---|
| 密码下限 **6** | 对齐**已上线前端**的权宜之计,**不是安全结论**;发起人已计划与前端 `minLength` 一起提到 8 |
| 成功体**不返回** `expiresAt` / `expiresIn` | "契约优先"的取舍(冻结形状里没有),不是不需要 —— 需要时按增量字段加 |
| 默认**内存仓储** | 为了 `pnpm dev` 零配置能跑,**不是生产方案** |
| `families` 由 `FamilyDirectoryPort` **转发**而非自己查库 | 为的是避免出现**第二份积分口径**;不要在 auth 里加 join |
| `scrypt` / 手写 HS256 | 当天"不许新增依赖"禁令的产物,已留单文件换入点(`registerHasher` / `TokenCodec`) |
