## 附录 A:本次初始化事故记录(给后来者避坑)

**事故 1:脚手架脚本产生中文乱码,差点提交坏代码**

- **现象**:用 shell 脚本(此处为 PowerShell here-string)批量生成文件时,`schema.prisma`、`constants.ts`、`types.ts`、`index.html`、`main.tsx` 里的中文字符串全部乱码(UTF-8 字节被按 GBK 解析),并导致 `constants.ts` 出现"未闭合字符串"语法错误、`schema.prisma` 出现行粘连。
- **发现方式**:`pnpm --filter @fcp/api test` 报 `Unterminated string literal`。
- **修复**:用 UTF-8 直接重写这 5 个文件;并做出一个架构决定 —— **持久化标识符改用 ASCII 码**(`open` / `pending_score` …),中文只出现在 UI 层(见 `INSTANCE_STATUS_LABEL` 与 `docs/DECISIONS.md` ADR-004 备注)。
- **教训**:**不要用 shell 脚本批量生成含中文的源码文件**;生成后必须跑一次 `pnpm -r typecheck` 与单测 —— 乱码自己不会暴露。

**事故 2:pnpm 12 不再读取 package.json 的 `pnpm` 字段**

- **现象**:`pnpm install` 报 `ERR_PNPM_IGNORED_BUILDS`,prisma / esbuild 的构建脚本被拦截,导致 `prisma generate` 与 vitest 启动异常。
- **修复**:配置移到 `pnpm-workspace.yaml` 的 `allowBuilds` 布尔映射(pnpm 12 的新写法,与 pnpm 10 的 `onlyBuiltDependencies` 列表不同)。
- **教训**:升级工具链后先查官方 settings 页,不要照抄旧版本的配置键名。

**事故 3:GitHub 认证踩坑**

- 本机 `git credential.helper` 指向 Git Credential Manager,在无人值守环境下会弹交互窗口并挂起(`git credential fill` 连续两次超时);`GIT_ASKPASS` **不能**直接指向 PowerShell 脚本(需 .bat/.cmd 包装,或改用 git 自身机制)。
- 最终可行做法:`git -c credential.helper= push`,配合**临时**把令牌放进远端 URL(`https://x-access-token:<token>@github.com/...`),推送成功后**立即** `git remote set-url` 改回不含令牌的地址。
- 另外:`gh auth login --with-token` 要求令牌含 `read:org`,仅 `repo` 权限会被拒绝 —— 此时直接走 REST API 更省事。
- **严禁**把令牌写进 `.git/config`、日志或任何提交。

**事故 4:按邮箱邀请协作者无法通过 REST API 完成**

- `PUT /repos/{owner}/{repo}/collaborators/email:<email>` 返回 404;**邮件邀请只有 GitHub 网页界面提供**。
- 可行做法:`…/settings/access` → Add people → 输入邮箱 → 选 "Invite to …" → 点 "Add <email>"。**若该邮箱已注册 GitHub 账号,界面会直接解析出用户名。**
- 本次结果:两位协作者均识别为已有账号并成功发出邀请(见附录 B)。
