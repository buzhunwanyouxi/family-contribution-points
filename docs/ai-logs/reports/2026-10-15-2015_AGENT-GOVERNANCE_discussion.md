## 3. 这次讨论产生的三个结论修正（会直接影响评估）

这一节能改变你对已有设计的判断，请优先看。

### 修正 1：AI 的"诚实标注"是**呈现层**，不是判定层

原设计里"标注已验证/未验证"被当作一个机制。**修正：判定权不能留在 AI 手里**——AI 说"我验过了"就是自陈，等于没约束。

**正确的三层**（我们推演后收敛的版本）：

| 层 | 判定对象 | 谁判定 | 失守靠谁救 |
|---|---|---|---|
| 1 候选集 | 我想到了哪些可能 | AI | **没人能救**——规则只能拿候选干活 |
| 2 可执行证据 + 规则 | 证据能不能证明声称 | **规则程序** | 第 1 层救不了 |
| 3 标注 | 我哪里没测 | AI | 第 2 层救不了 |

**关键句**：`文件存在` 是可执行的，但证明不了"文件内容正确"。**证据必须能覆盖声称的范围。**

### 修正 2：A2A 监管（第二个 AI 复核）收益**不来自第二个 AI**

我（讨论 A 的一方）起初判断"多智能体监管抓不住盲区、收益接近 0"。**看了腾讯云那篇的实际经验后修正**：

| 形态 | 有效吗 |
|---|---|
| 让第二个 AI"复核一下" | ❌ 同一个盲区求交集，且会制造假可信度 |
| **给第二个 AI 一套独立的检查视角/清单** | ✅ 那篇里评审 Agent 抓到过编码 Agent 漏掉的渠道判断逻辑（潜在线上故障） |

**界线**：收益来自"**第二套检查视角**"，不是"第二个 AI"。**没有独立检查清单的复核 = 第二个点头的。**

⚠️ 那篇文章没处理的风险（我们保留了）：**复核盖章会制造假可信度**——被复核过的错误更难被发现。

**对我们最直接的推论**：`ci-needs-workflow-scope` 这类事情，加第二个 AI 复核没用，**要的是能独立测量或独立查询的一条通道**。

### 修正 3：规则筛"删除"候选会制造假可信度 —— 应改为"标注"

我们推演的"候选集 + 规则筛"方案里，**筛除动作本身有问题**：

```
筛对了：   {2,6} → 否掉 2 → 输出 {6}      ✅
筛错了：   {2,6} → 否掉 6 → 输出 {2}      ❌
筛子崩了： {2,6} → 异常被吞 → 输出 {2}    ❌
```

**三种情况使用者看到的一模一样**，而且"被严谨筛过"这个标签让人**更信任**它。

**修正**：把"删除"换成"**标注**"（refuted / unresolved / verified），候选全部保留、带状态和排除依据。**三个状态，不是两个**——只有两态（通过/否决）的规则筛，会在"证据看不懂"时被迫猜一个。

### 提案 ① 把 `AGENTS.md` 从 212 行压回 ~100 行索引

**依据**：腾讯云那篇引 OpenAI 经验——`AGENTS.md` 写成百科全书会导致"**所有内容都重要 = 没有内容重要**"，后压到 ~100 行当索引与地图。

**提案**：**不是删规则，是分层**——`AGENTS.md` 只留禁令 + 16 步索引 + 必读入口；"为什么"和历史案例挪到 `docs/` 按需加载。

**代价**：一次搬家（约 1 小时）。**收益**：每个新协作者少读 100 行；同时缓解"只增不减"。

### 提案 ② 停滞计数器（"熔断"的燃料）

**问题**：AI 卡在一个错前提上反复调参时，**它自己不觉得卡**——它觉得在逼近正确答案。

**提案**：每轮追加 5 行到一个固定位置（`ops` 日志或收件箱）：

```markdown
## 停滞计数
- 当前方向:____
- 它建立在什么上:____              ← 如果是推断,写"推断"
- 这个依据验证过吗:是 / 否           ← 写"否"的,就是熔断的靶子
- 连续无信息增益轮数: N / 4
- 本轮观察(只写原始输出,不写叙事):____
```

**三条必须钉死的规则**（否则机制会静默失效）：

1. **"新信息"是封闭集合，排除叙事**：只算命令原始输出/测量值/报错/文件变化；**不算**"我尝试了""我发现""看起来似乎""我调整了参数"。
   **机械判据**：删掉本轮所有叙事，只留原始输出，**与上一轮逐字节相同 → 本轮无新信息**。
   > 不写死这条，计数器会被 AI 的叙事灌水，**熔断永不触发，而且不报错**——那是机制自己的静默失败。
2. **阈值 4**：来源是 8D 复盘的实测原话"**四五轮全部没有产生有效信息**"。
3. **计数器必须落地**（不能只活在上下文里）：依据是 `144c1ca` 那次"上一会话留下未提交工作 → 生成物是旧的 → 任何人照流程读都会读到过期状态"。

**❓请评估**：这 5 行放哪里最不容易被漏？（ops 日志是收工才写，而停滞是过程中发生的）会不会和现有 16 步打架？

### 提案 ③ 熔断出口 + 回退映射表

**熔断出口不能是"再想想"**，否则只是把"闷头往前撞"变成"闷头重新想一遍"。

**提案出口**：回到那个**未验证的依据**，并**就地打断**上报：

```markdown
【熔断 · 需要你一句话】
我在这个方向上连续 4 轮没有得到任何新信息。
它建立在一个**没验证过的前提**上:____(这条我一次也没测过)
A. 用 1 分钟测掉它(命令已备好:____)     ← 推荐
B. 换方向(但我需要你确认哪个更值)
```

**并且：熔断不许静默换方向**——否则它自己就变成一个静默事件（正是本项目一直在防的）。

**回退映射表**（腾讯云那篇有现成形状：CI 失败回退到测试编写、编译错回退到编码、需求不符回退到需求分析）：

| 失败类型 | 回退到 | 现状 |
|---|---|---|
| 编译 / 类型错误 | 写代码 | ✅ 有 |
| 测试 0/0 或断言异常 | 测试编写 | ⚠️ 缺 |
| 两 PR 各自通过、一起冲突 | **合并预演** | ✅ 有（做过一次，很好用） |
| **连续 4 轮无信息增益** | **验证那个未验证的依据** | ❌ **新增** |

**另外值得照抄一条**：那篇的"评审循环上限"——**需求评审最多 3 轮、编码/测试评审最多 2 轮，超出升级人工**。这是熔断的生产先例，出口形态和我们提的一致。

**❓请评估**：回退映射表该放 `AGENTS.md` 还是按需文档？熔断打断的频率会不会太高？

### 提案 ⑤ 复审触发点（治"没人宣告的过时"）

**问题**：规则分三类，**只有一类会静默失效**：

| 类型 | 例 | 会有人宣告吗 |
|---|---|---|
| **不变量** | 积分恒等式、结算唯一实现、禁令 1/2/7 | 不会失效 |
| **事故型** | 坑 5「信用分机制已经被删除」 | ⚠️ 决定被埋了，读不出是"永久别再加"还是"当前没有" |
| **外部依赖型** | 必读 7「细粒度令牌不被支持」 | ❌ **外部世界变了，没有任何人需要做决定** |

**最隐蔽的一例**：必读 7 开头写着「**只有当你推不上去时（403）才读**」——这是**症状触发式**规则。**症状一消失，它就永远读不到了，但仍挂在必读表里占位。**

**提案**：给**外部依赖型**规则各加一段"什么时候回来看我一眼"，**挂事件不挂日期**：

```jsonc
{
  "rule": "协作者只能用经典令牌(细粒度令牌在协作者身份下不被支持)",
  "valid_while": "GitHub 仍不支持『以协作者身份用细粒度令牌推送』",
  "recheck_at": "每当有新协作者加入时",     // ← 事件,不是日期
  "recheck_how": "扫一眼官方文档对应小节",
  "if_broken": "提一条 spec-gap"
}
```

**判断依据**：挂日期到点了没人在乎；挂"有新协作者加入"——**那一刻正好有人被这条规则挡住，问题必然被想起**。

**范围**：我筛了一遍，37 条里**真正需要的大概 5 条**（必读 7 的两条、坑 5、以及同类）。**其余 32 条不要动**——给不变量加字段只是增加噪音。

**❓请评估**：这 5 条我挑得对吗？标准是"**它错了，会有人立刻发现吗**"——错了没人立刻发现的才需要加。

## 6. ❌ 明确建议**不要**做的（避免你重复踩坑）

这几条是讨论中推演过、**结论是不做**的：

| 方案 | 为什么不做 |
|---|---|
| **"AI 自迭代 spec 框架"**（AI 工作时自己改规则） | **违反禁令 8**。被约束者不得修改约束；且本项目一个月只有约 3 个 spec 相关反例，**燃料不够，框架会空转** |
| **让 AI 自己在输出端标注不确定性** | 判定权在 AI 手里 = 自陈，等于无约束。标注只能当**呈现层**（见修正 1） |
| **完整候选集 + 证据对象 + 三态输出** | 解的是产出端，而本项目最贵的失败在过程端；成本高、当前不需要 |
| **第二套专家团 / MCP 集成 / 知识库三层结构** | 腾讯云那篇是 10 万行存量 Java 应用的解法，**本项目的规模上这套会变成负债本身** |
| **用"失败次数"做熔断** | **8D 那次的失败次数是 0**——命令跑完、不报错、波形没变。**必须数"无信息增益"，不能数"失败"** |

| 观测 | 结论 | 动作 |
|---|---|---|
